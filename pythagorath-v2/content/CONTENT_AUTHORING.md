# قواعد تأليف المحتوى (فيثاغورث)

كل المحتوى يدخل القاعدة عبر **API لوحة الإدارة فقط** (المصدر الواحد). قبل الإدخال،
يلتزم كل سؤال بالقواعد التالية لضمان إجابة واحدة قاطعة لا تحتمل تأويلاً.

## القاعدة ١ — الصياغة القاطعة (إلزامية)

أي سؤال يستخدم **قبل / بعد / فوق / تحت** يجب أن يكون قاطعاً بإحدى طريقتين:

1. إضافة **«مباشرةً»** — مثال:
   - ❌ «ما العدد الذي يأتي قبل ٦٠؟» (يحتمل ٥٩ أو ٥٠)
   - ✅ «ما العدد الذي يأتي قبل ٦٠ مباشرةً؟» (٥٩ قاطعة)
   - في لوحة المائة: «فوق ٦٨ مباشرةً» = الخلية أعلاه (−١٠)، «تحت ١٨ مباشرةً» = الخلية أسفله (+١٠).

2. أو صياغة **عدّ صريحة** (تسلسل/نمط) لا لبس فيها — مثال:
   - ✅ «أكمل: ١٦، ١٧، ١٨، ؟»
   - ✅ «العدّ بالخمسات: ٥، ١٠، ١٥، ؟»

صياغات قاطعة أصلاً (لا تحتاج «مباشرةً»): «بين أي عقدين»، «نقطة المنتصف بين … و …»،
«العقد الذي يلي/يسبق»، «أقرب إلى أي عقد»، «أكثر من … وأقل من …».

## القاعدة ٢ — الأرقام الهندية

أرقام المحتوى هندية (٠١٢٣٤٥٦٧٨٩) حسب المنهج. تُخزَّن في `payload` (JSON) وتمرّ
عبر الـAPI دون تحويل إلى الأرقام الغربية. (تُحفظ مهرّبة `\uXXXX` في SQLite وتُفكّ
مطابقة للمصدر — مؤكَّد بفحص round-trip.)

## القاعدة ٣′ — الصعوبة والإتقان (الصعوبة المرغوبة)

عتبة الإتقان للمهارات التأسيسية = **0.9** (في `skills.mastery_threshold`، قابلة للتعديل).
ومنطق الإتقان يشترط **سؤالاً صعباً واحداً على الأقل (`difficulty = 3`) محلولاً بنجاح
ضمن نافذة الـ٥ الأخيرة** — لا إتقان بحلّ السهل فقط.

**أثر إلزامي على التأليف:** كل مهارة **يجب** أن تحوي سؤالاً واحداً على الأقل بصعوبة ٣،
وإلا تعذّر إتقانها أبداً. وزّع الصعوبة (١ سهل، ٢ متوسط، ٣ صعب) في كل بنك مهارة.

> ⚠ ثغرة قائمة: مهارة «التقدير» (الوحدة الأولى) بلا أي سؤال صعوبة ٣ → غير قابلة للإتقان
> حتى يُضاف لها سؤال صعب عبر `POST /api/admin/questions`.

## أنواع التفاعل (interaction_type)

تختار الواجهة آلية الإدخال حسب `interaction_type`:

### `choice` — اختيار من متعدّد (افتراضي)
```json
{ "interaction_type": "choice",
  "payload": { "prompt": "...", "answer": "٤٨", "choices": ["٤٦","٤٨","٥٧","٤٩"] } }
```

### `number-line` — خط أعداد تفاعلي (الطفل يضع علامة بالنقر)
```json
{ "interaction_type": "number-line",
  "payload": { "prompt": "ضع العلامة على العدد ٦٠",
               "answer": "٦٠",
               "line": { "min": 0, "max": 100, "step": 10 } } }
```
- **بلا `choices`** — الإجابة تُنتَج من موضع العلامة.
- العلامات تظهر عند `min, min+step, …, max` بأرقام هندية؛ الطفل ينقر الموضع → «اخترت ٦٠» → «تأكيد».
- `answer` بأرقام هندية ليطابق ناتج الودجة (التصحيح في الخادم مقارنة نصّية، بلا تغيير).
- يجب أن يكون `answer` واقعاً على إحدى علامات الخط (`min + k·step`).
- (السحب مؤجَّل؛ النقر فقط حالياً.)

### `tap-count` — العدّ بالقفز بالمجموعات
```json
{ "interaction_type": "tap-count",
  "payload": { "prompt": "كم تفاحة في كل السلال؟",
               "answer": "٢٠",
               "count": { "emoji": "🍎", "groups": 4, "per_group": 5 } } }
```
- يعرض `groups` سلالاً، كل سلة فيها `per_group` عنصراً. الطفل ينقر كل سلة ليعدّ
  بالقفز (٥، ١٠، ١٥، ٢٠ — شارة تراكمية + «العدّ: X»). الإجابة تُبنى بالعدّ القفزي.
- **بلا `choices`.** `answer` = `groups × per_group` بأرقام هندية (يطابق ناتج الودجة).
- **لا تجعله تافهاً:** لا تعرض عدداً ظاهراً يساوي الإجابة مباشرةً؛ المهارة هي العدّ
  بالقفز بالمجموعات (لو عدّ سلالاً أقل → إجابة خاطئة).
- (نقر فقط؛ السحب مؤجَّل.)

### `fill` — تعبئة رقمية (لوحة أرقام هندية على الشاشة)
```json
{ "interaction_type": "fill",
  "payload": { "prompt": "٧ + ؟ = ١٠", "answer": "٣", "fill": { "max_digits": 2 } } }
```
- الطفل يُدخل الرقم عبر لوحة هندية على الشاشة (لا كيبورد النظام) → «تأكيد».
- **بلا `choices`.** `answer` بأرقام هندية. `fill.max_digits` اختياري (افتراضي ٣).
- للقيمة المكانية وأزواج الأعداد. **يقيس مهارة** (مكمّل/ناتج)، لا إجابة ظاهرة.

## القاعدة ٣ — بنية السؤال

`payload = { "prompt": "...", "answer": "...", "choices": ["...", ...], "visual"?: {"type","data"} }`

- `answer` يطابق أحد `choices` تماماً (التصحيح في الخادم بمقارنة نصّية مُطبَّعة).
- `interaction_type` يصف نوع التفاعل (choice / number-line / counting-objects …).
- `visual` اختياري؛ عند وجوده تُصيّره الواجهة عبر `QuestionVisual`.

## المرجع الحيّ

النسخة المرجعية للوحدة الأولى مُصدَّرة من القاعدة (المصدر الواحد) إلى
`content/unit1_grade2_math.json`، وتُحدَّث بإعادة التصدير بعد أي تعديل
(`scripts/export_unit1.py`). لا تُعتمد ملفات خارج المشروع كمرجع.

## افتراض ترتيب المهارات (التشخيص التكيّفي §2)

منطق **الهبوط التتابعي** في التشخيص (`services/placement.py`) يفترض ترتيباً
**خطّياً** للمهارات: كل مهارة تعتمد على ما قبلها في حقل `order`، فالمشي «أول مهارة
غير مجتازة» والتجاوز (placed-out لما قبلها) يفترضان أن تجاوز مهارة يعني تجاوز كل
أسبقها. هذا صحيح للوحدة الأولى (سلسلة ١→٢→٣→٤ مع تفرّع بسيط يحترم الترتيب).

**يجب مراجعة هذا الافتراض** إن أُضيفت وحدة بمهارات **متوازية/مستقلة** (مهارتان بلا
علاقة أسبقية بينهما، أو رسم تبعية غير خطّي): عندها «أول مهارة غير مجتازة بالترتيب»
قد تتجاوز ظلماً مهارةً مستقلّة لم تُختَبر. الحلّ المستقبلي: اجعل الهبوط يحترم رسم
المتطلبات الفعلي (`skill_prerequisites`) لا ترتيب `order` وحده. البوّابة نفسها
(`unmet_prerequisites`) تحترم الرسم سلفاً؛ منطق الهبوط فقط هو الخطّي.

## ⛔ التشخيص التكيّفي §2 — معطّل وظيفياً عمداً (تجميد Phase-1)

التنسيب **يقترح نقطة بداية ولا يفتح عبوراً**. سابقاً كان `placed_out` (من التشخيص)
يَستوفي متطلّب البوّابة، فيفتح للطفل المُنسَّب مهاراتٍ لم يُتقنها — أي **عبور بلا
إثبات فهم**، وهو ما يناقض جوهر فيثاغورث (الإتقان قبل الانتقال). وبما أنّ بوّابة
الفهم الصحيحة (نقل عبر **عائلتين تمثيليتين**) لا يمكن أن تعمل الآن — البنك **أحادي
العائلة** (تمثيل مقداري فقط: خطّ أعداد/اختيار) — لا نرقّع البوّابة بعائلة لا توجد،
بل **نجمّد أثر التنسيب**:

- `mastery_engine.unmet_prerequisites`: المتطلّب يُستوفى بالإتقان **وحده**
  (`satisfied = mastered`). `placed_out_skill_ids` محفوظة لكنّها **غير مستخدَمة في
  البوّابة** عمداً.
- العرض (`skillmap.py` + `parent_report.py` + واجهتهما): لا حالة «تم تجاوزها»
  بصرياً — خريطة المُنسَّب تطابق خريطة طفل جديد. (تجميد البوّابة دون العرض يُنتج
  كذباً بصرياً: «اجتزتَ لكن لا تعبر».)
- يبقى من التنسيب: سجلّ `LearningPath` ورسالة `DiagnosticScreen` فقط — أثرٌ نصّي/
  تاريخي بلا تنقّل. التشخيص والتنسيب **لم يُحذفا** من الكود؛ جُمّد أثرهما ليُعادا حين
  تكتمل العائلات.

**الأثر المرئي:** الطفل المُنسَّب (مثل نورة) يبدأ الآن من المهارة ١ كأي طفل جديد.
هذا تراجع وظيفي مقصود وصادق — ميزةٌ معطّلة بصدق خيرٌ من ميزةٍ عاملة تخالف غايتها.

### الديون الثلاثة المعروفة المؤجّلة (تُحسَم في اشتقاق الشبكة، لا تُرقَّع الآن)
أ. **بوّابة الفهم في التنسيب معطّلة** — البنك أحادي العائلة، فقياس النقل بعائلتين
   غير ممكن بعد.
ب. **العائلات التمثيلية غير مؤلَّفة** — بناؤها (الحقل السادس في قالب العقدة) مؤجّل
   إلى مرحلة اشتقاق الشبكة من الوعد؛ هناك تُؤلَّف كجزء من تعريف كل عقدة، وعندها يكتمل
   التشخيص دستورياً (تنسيب يقيس فهماً لا تجاوزاً).
ج. **الهبوط الخطّي على رسم متفرّع (DAG)** — منطق «أول مهارة غير مجتازة» يتبع `order`
   لا `skill_prerequisites`؛ يُحسَم في الاشتقاق مع تعريف دلالة التنسيب على الفروع
   المتوازية.
