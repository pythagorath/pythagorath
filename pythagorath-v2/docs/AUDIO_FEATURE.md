# ميزة الصوت — تسجيل المعلّم لكل سؤال (وثيقة تصميم)

**الحالة:** ✅ **مبنية ومُثبتة** (الخلفية + استوديو الصوت في اللوحة + التشغيل في
واجهة الطفل مع تراجع آمن). أُنجزت بعد ودجة التعبئة وقبل صياغة المحتوى. التخزين:
ملفات على القرص تحت `uploads/audio/q{id}.webm` + صفّ `question_audio` (اخترنا
ملفات على الخادم لا BLOB، حسب طلب المالك).

**الهدف:** استبدال `SpeechSynthesis` المؤقّت بصوت **بشري مسجَّل** لكل سؤال: المعلّم
يسجّل صوته يقرأ السؤال من لوحة الإدارة (MediaRecorder في المتصفّح)، يُرفَق بالسؤال
ويُخزَّن مرتبطاً بمعرّفه، ويُشغَّل في واجهة الطفل (مع `SpeechSynthesis` كاحتياطي).

§3: الصوت أساسي لا ثانوي — كل سؤال يُنطَق، وزر إعادة الاستماع دائم.

---

## ١. نموذج البيانات والتخزين

جدول جديد **`question_audio`** (صوت واحد لكل سؤال؛ التسجيل الجديد يستبدل القديم):

| الحقل | النوع | ملاحظة |
| --- | --- | --- |
| `question_id` | PK, FK→questions.id **ON DELETE CASCADE** | حذف السؤال يحذف صوته |
| `content_type` | str | مثل `audio/webm` |
| `audio` | LargeBinary (BLOB) | بايتات التسجيل |
| `byte_size` | int | للتحقّق/العرض |
| `updated_at` | datetime | آخر تسجيل |

**قرار التخزين (الآن):** BLOB داخل قاعدة البيانات — يحفظ مبدأ «مصدر واحد»، نسخ
احتياطي بسيط، ومقاطع قصيرة (ثوانٍ، عشرات الكيلوبايت). **مسار التوسّع لاحقاً:** عند
الكِبَر، يُنقَل التخزين إلى object storage ويبقى في الجدول مرجع/مفتاح فقط — دون تغيير
الواجهات. (migration واحد عبر Alembic.)

يُضاف للقراءة: حقل محسوب `has_audio: bool` في مخطط قراءة السؤال (admin + child)
ليُعرف وجود تسجيل دون جلب البايتات.

## ٢. نقاط الـAPI

| الطريقة | المسار | الوظيفة |
| --- | --- | --- |
| `POST` | `/api/admin/questions/{id}/audio` | رفع/استبدال (multipart؛ ملف التسجيل). تحقّق: `content_type` صوتي، الحجم ≤ حدّ (مثلاً ٢MB). يُنشئ/يحدّث صف `question_audio`. |
| `GET` | `/api/questions/{id}/audio` | بثّ الصوت (StreamingResponse بالـ`content_type`) — للاستماع في اللوحة وللتشغيل عند الطفل. 404 إن لا صوت. |
| `DELETE` | `/api/admin/questions/{id}/audio` | حذف التسجيل. |

(نقاط `admin/*` خلف صلاحية المدير عند توفّر المصادقة؛ الآن مفتوحة كبقية اللوحة.)

---

## ٣. لوحة الإدارة (التأليف)

في نموذج تأليف السؤال، قسم **«🎙 صوت السؤال»**:
- زر **«إضافة صوت / تسجيل»** → طلب إذن الميكروفون → **MediaRecorder**
  (`audio/webm;codecs=opus`) → **تسجيل (ابدأ/أوقف)**.
- **استماع** (معاينة المقطع قبل الحفظ) · **إعادة تسجيل** · **حفظ** (رفع إلى POST).
- إن وُجد تسجيل سابق: استماع / إعادة تسجيل / حذف.
- مؤشّر مدة ومستوى تسجيل بسيط (اختياري).

تدفّق: `getUserMedia({audio})` → `MediaRecorder` → تجميع `Blob` → `FormData` →
`POST .../audio`.

---

## ٤. واجهة الطفل (التشغيل)

- يستبدل `lib/speak.ts` المؤقّت بدالة **`playQuestionAudio(questionId, fallbackText)`**:
  1. إن كان `has_audio` → تشغيل `GET /api/questions/{id}/audio` (عنصر `<audio>`/`Audio()`).
  2. عند الخطأ/الغياب → `SpeechSynthesis(fallbackText)` (الاحتياطي الحالي).
- زر 🔊 «إعادة الاستماع» يعيد تشغيل الصوت (موجود الآن، يُعاد توصيله).
- تشغيل تلقائي عند ظهور السؤال (كما الآن) لكن بالتسجيل إن وُجد.

---

## ٥. الترتيب والاعتبارات

- **التتابع:** يُبنى بعد `fill`، قبل صياغة المحتوى — ليرفق المؤلّف صوتاً لكل سؤال أثناء كتابته.
- **الصيغة:** `webm/opus` افتراض MediaRecorder؛ مدعوم في المتصفّحات الحديثة. (Safari قديم قد يحتاج `audio/mp4` — يُكتشف بـ`MediaRecorder.isTypeSupported`.)
- **الحجم/التحقّق:** حدّ أعلى للحجم ونوع المحتوى عند الرفع.
- **الحذف المتتالي:** FK CASCADE يضمن ألا يبقى صوت يتيم.
- **لا يكسر القائم:** الحقل `has_audio` والاحتياطي يبقيان الأسئلة بلا تسجيل تعمل بـ`SpeechSynthesis`.
